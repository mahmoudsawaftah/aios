---
name: aios-plan
description: Use before implementing a new feature or behavior change that spans multiple steps, more than three files, or architecture, database, or security boundaries. Do not use for a one-line fix or read-only question.
---
1. Read the project's AGENTS.md, existing plans, issue/task details, and relevant code.
2. State the goal, scope, non-goals, constraints, acceptance criteria, affected areas, implementation stages, verification commands, and rollback approach.
3. For more than three files, architecture, data, or security changes, create or update the project's PLANS.md. Reuse an existing plan source if the project already has one.
4. Keep the plan concise and update its status as work progresses.
5. Do not implement beyond the task's authorized scope.
